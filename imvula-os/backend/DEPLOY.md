# Imvula OS Backend — Deployment Guide

## Production stack

| Layer | Service | Notes |
|---|---|---|
| Backend API | Render (Frankfurt, free tier) | Cold starts after 15 min idle |
| Database | Render PostgreSQL (free tier) | 90-day inactivity expiry |
| Frontend | GitHub Pages | https://zithaewarty-11.github.io/imvulalabs.github.io/ |
| AI Provider | Mock (default) | Flip to `deepseek` when a customer pays |

## First-time deploy

1. Sign up at https://render.com (no credit card)
2. New → Blueprint
3. Connect GitHub repo `zithaewarty-11/imvulalabs.github.io`
4. Render reads `render.yaml` and provisions:
   - Web service `imvula-os-api`
   - PostgreSQL database `imvula-os-db`
5. Wait ~5 min for first build
6. Copy the service URL (e.g. `https://imvula-os-api.onrender.com`)
7. Update `js/imvula-config.js` in the frontend — set `PROD_API_BASE_URL` to that URL
8. Commit + push → GitHub Pages rebuilds automatically

## Environment variables (managed in Render dashboard)

| Var | Source | Action |
|---|---|---|
| `JWT_SECRET` | Auto-generated by Render | Don't touch |
| `DATABASE_URL` | Auto-wired to PostgreSQL | Don't touch |
| `ALLOWED_ORIGINS` | `render.yaml` | Update if frontend domain changes |
| `AI_PROVIDER` | `mock` | Change to `deepseek` when ready |
| `DEEPSEEK_API_KEY` | — | Add when switching to real AI |

## Free tier limitations

- Web service spins down after 15 min idle (~30s cold start)
- PostgreSQL deleted after 90 days of inactivity; 1 GB storage limit
- 100 GB bandwidth/month

## Rolling back a bad deploy

1. Render dashboard → service → Events tab
2. Click the last known-good deploy → "Redeploy"
3. Database stays untouched (migrations are additive)

## Verifying after deploy

    curl https://<your-service>.onrender.com/health
    # Expected: {"status":"ok","service":"imvula-os"}
